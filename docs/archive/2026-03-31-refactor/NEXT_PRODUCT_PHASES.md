# Next Product Phases

> Historical roadmap note.
> This file reflects an older priority order and is no longer the canonical source of current product sequencing.
> Current direction is defined by the product bible and refactor masterplan.

Короткий ориентир по следующим крупным этапам развития проекта после текущего блока `/arcs`.

Статус: historical / partially stale roadmap

## 1. Ближайший порядок

1. Небольшой cosmetic pass
2. `PAGER 03`
3. Большой audit и refactor roadmap
4. Масштабный refactor по пакетам

## 2. Phase A: Cosmetic Polish

Короткий проход по визуальным шероховатостям, не уходя в глубокий дебаг.

Цель:

- снять раздражающие мелочи в UI;
- быстро улучшить ощущение продукта;
- не застрять в бесконечной полировке.

Примеры работ:

- мелкие правки `/arcs`;
- отступы, типографика, визуальные несостыковки shell;
- локальные UI-шероховатости, которые уже видны глазами.

## 3. Phase B: PAGER 03

Разработка полноценной системы сообщений.

Основное направление:

- личные переписки между пользователями;
- inbox / список диалогов;
- unread / read state;
- composer и отправка сообщений;
- системные письма от форума пользователю.

Что важно продумать заранее:

- модель `threads / participants / messages`;
- unread markers;
- системные сообщения как отдельный тип, а не костыль;
- границы между `direct messages` и `forum mail`.

Ожидаемый результат:

- в shell появляется реально рабочий `PAGER 03`;
- у проекта появляется личный коммуникационный слой;
- системные уведомления получают нормальный дом.

## 4. Phase C: System Audit

После `PAGER 03` проводится большой архитектурный аудит проекта.

Цель:

- найти слабые места;
- собрать список перегруженных файлов и временных костылей;
- оценить, где логика дублируется;
- понять, где проект тратит лишние ресурсы;
- зафиксировать, что нужно переосмыслить перед большим рефакторингом.

Результат:

- карта проблем;
- приоритеты;
- план рефакторинга не “на глаз”, а по фактическим наблюдениям.

## 5. Phase D: Refactor Execution

Пакетная переработка проекта после аудита.

Направления:

- server-side architecture;
- API layer;
- data model / Prisma;
- UI composition;
- performance;
- naming consistency;
- removal of legacy hacks and duplicated logic.

Принцип:

- не один гигантский хаотичный рефакторинг;
- а несколько управляемых пакетов изменений с проверкой после каждого.

## 6. Общая идея

Сейчас проект уже вышел из стадии “собрать MVP любой ценой”.

Следующий цикл должен быть таким:

- чуть подровнять внешний слой;
- построить новый важный блок `PAGER 03`;
- затем уже переосмыслить и улучшить весь форум на более зрелом уровне.
